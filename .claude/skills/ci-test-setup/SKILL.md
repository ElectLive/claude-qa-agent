# WAY 10 — CI Test Setup

Tests are written to `./qa-artifacts/`, which is **gitignored** in this
project, so a pipeline can't see them. This WAY copies the runnable suite
into the **application's** repository and adds GitLab CI jobs for it.

## Step 1: Gather inputs
- **App repo path** (a local clone). Required, ask if missing
- Which projects to run: `e2e`, `api`, or both (default: whichever exist in `qa-artifacts/playwright.config.ts`)
- Triggers (default: MR pipelines + default branch + schedules)

## Phase 1: Export the suite → `<app-repo>/qa-tests/`
Copy from `qa-artifacts/`: `package.json`, `package-lock.json`, `playwright.config.ts`, `steps/`, `test-cases/`, `visual-baselines/`.

**Never copy:** `node_modules/`, `.features-gen/`, `runs/`, `api-responses/`, `.auth/` (saved sessions = credentials), `.env`.

Then check the exported config:
- `baseURL` must come from `process.env.BASE_URL` / `API_BASE_URL`. A hard-coded URL gets flagged
- `storageState: '.auth/…'` won't exist in CI. Flag it and propose a setup project (`auth.setup.ts`) that logs in with masked CI variables (`QA_USER`, `QA_PASSWORD`) and saves the state, so the `e2e` project `dependencies: ['setup']`. Write the file only if the user agrees
- Add a JUnit reporter used only in CI: `...(process.env.CI ? [['junit', { outputFile: 'runs/' + (process.env.RUN_ID ?? 'latest') + '/junit.xml' }]] : [])`

## Phase 2: CI include → `<app-repo>/.gitlab/ci/qa-tests.gitlab-ci.yml`
Read the exact `@playwright/test` version from `package-lock.json`. The image tag **must** match it.

```yaml
# 🤖 Generated by DevOps QA Agent — review before relying on this test.
.qa-base:
  image: mcr.microsoft.com/playwright:v<version>-noble
  stage: test
  variables:
    RUN_ID: ci
  before_script:
    - cd qa-tests
    - npm ci
    - npx bddgen
  artifacts:
    when: always
    expire_in: 14 days
    paths: [qa-tests/runs/]
    reports:
      junit: qa-tests/runs/ci/junit.xml
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
    - if: $CI_PIPELINE_SOURCE == "schedule"

qa-e2e:
  extends: .qa-base
  script:
    - npx playwright test --project=e2e

qa-api:
  extends: .qa-base
  script:
    - npx playwright test --project=api

qa-update-baselines:          # only if @visual tests exist
  extends: .qa-base
  rules:
    - when: manual
  script:
    - npx playwright test --project=e2e --grep @visual --update-snapshots
  artifacts:
    paths: [qa-tests/visual-baselines/]
```

Then add `include: [{ local: .gitlab/ci/qa-tests.gitlab-ci.yml }]` to the app's `.gitlab-ci.yml` (and a `test` stage if it defines `stages` without one).

**Visual baselines:** screenshots rendered on Windows/macOS won't match the Linux CI image. Tell the user to run `qa-update-baselines` once, download its artifact, and commit those baselines. Don't commit the local ones.

## Phase 3: Validate
Lint the combined config with `validate_ci_lint` (`content` = the app's `.gitlab-ci.yml` with the include inlined). Fix and re-lint until it's valid.

## Phase 4: Hand over (no commit, no push)
Print:
- the files written or changed (`git -C <app-repo> status --short`)
- the CI/CD variables to create in GitLab (Settings → CI/CD → Variables), all **masked**: `BASE_URL`, `API_BASE_URL`, `API_TEST_TOKEN`, plus `QA_USER`/`QA_PASSWORD` if using a setup project
- the next steps: commit on a branch, open an MR, and watch the `qa-*` jobs. `diagnose it` (WAY 5) explains failures, and its JUnit report names the `Test#<nn>`

Keeping the copy current: re-run this WAY after `write-tests`/`e2e-session` add tests. It overwrites `qa-tests/` from `qa-artifacts/`, after showing the diff.
